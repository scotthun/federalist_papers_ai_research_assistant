- (capability) CAP-1: Browse — user can browse a complete list of all 85 Federalist Papers (number, title, author(s)). Success: browse view lists exactly 85 entries, each linking to its full Paper Reader.
- (capability) CAP-2: Search — user can search by paper number, author, title, exact keyword, or semantic concept (hybrid where easy). Success: each mode returns correct/relevant results against the retrieval evaluation dataset.
- (capability) CAP-3: Ask the Archive — user asks a natural-language question, system returns an answer grounded only in retrieved passages. Success: no answer includes a claim without a server-verified citation; eval dataset's expected paper appears in top-K.
- (capability) CAP-4: Tiered confidence response — system responds via one of three code-decided tiers (confident answer / clarify-with-best-guess / refuse-insufficient-evidence) gated on retrieval similarity, never LLM self-reported confidence. Success: given fixture retrieval scores in each band, the corresponding tier's response is produced deterministically, and the LLM is never called below clarifyThreshold.
- (capability) CAP-5: Verified citations — every substantive answer includes citations (paper number, title, chunk) server-verified against actually-retrieved chunks before reaching the user. Success: any citation reaching the frontend maps to a chunk ID retrieved for that request; a mismatch triggers one retry then a safe fallback, never a stripped citation served as if fully backed.
- (capability) CAP-6: Passage-in-context navigation — user can open a cited paper and see the cited passage in context. Success: clicking a citation opens the correct paper's reader and surfaces the cited passage without discarding the original question/answer.
- (capability) CAP-7: Independent source verification — user can follow a link from any paper to its authoritative original source to verify the text independently of the app. Success: every FederalistPaper row has a non-null, resolvable sourceUrl, displayed as a quiet tag near the paper title in the reader.
- (constraint) Postgres + pgvector only for vector search — no separate vector database (Pinecone/Weaviate/Chroma/Qdrant). Demonstrates vector search living alongside relational data.
- (constraint) AI layer is TypeScript-only via LangChain.js — no Python anywhere in the stack.
- (constraint) No authentication or user accounts — bends rate-limiting toward IP/global throttling instead of per-user quotas, and rules out per-user personalization features.
- (constraint) Nx monorepo: apps/web, apps/api, libs/ai|database|documents|retrieval|shared — one library per concern, not one microservice per library.
- (constraint) Ingestion + citation source is locked to the Avalon Project (avalon.law.yale.edu/18th_century/fed{NN}.asp), chosen via bmad-deep-recon comparison against LOC/Founders Online/Congress.gov on credibility, scriptability, and independently-verified ~18-year URL stability; empirically fidelity-checked against LOC's text after Avalon disclosed no provenance statement of its own. Full rationale in the decisions companion and docs/planning/research/technical-federalist-papers-ingestion-source-2026-08-24/research.md.
- (constraint) Deterministic application logic is preferred over LLM judgment wherever code can decide reliably — governs confidence tiering (never LLM self-reported), citation verification (set-membership check, not model opinion), and confidence field derivation (from similarity score, not self-report).
- (constraint) Author is a many-to-many relation (Author <-> FederalistPaper), not a string column, to represent disputed/joint authorship (e.g. Nos. 18-20, 62-63) without picking a side.
- (constraint) chunkId is ephemeral, valid only within its originating request/response cycle — never persisted, bookmarked, or shared as a stable identifier, since re-ingestion deletes and recreates DocumentChunk rows.
- (constraint) Retrieval filters (paperNumber/author) must apply in the SQL WHERE clause before the top-K LIMIT, never applied post-hoc on an already-limited result set.
- (constraint) AI provider abstraction (generateAnswer/generateStructuredOutput/generateEmbedding) is mandatory — application code never depends directly on OpenAI/Anthropic/any single provider's SDK.
- (constraint) Rate limiting: per-IP throttle required at MVP (no new infrastructure); a global daily cap on AI-backed requests is documented but deferred past MVP; no Redis needed at this project's single-process scale for either tier. Validated against production RAG practice and academic abstention literature via bmad-deep-recon (docs/planning/research/technical-rag-confidence-tiering-2026-08-24/research.md) — three-tier confidence design is a legitimate borrow from NLU confidence-banding (Rasa, Amazon Lex), not a native RAG pattern; similarity score alone is a known-weak abstention signal, which is why citation verification stays mandatory in every tier.
- (constraint) WHY: portfolio/learning project demonstrating RAG, semantic search, pgvector, provider-agnostic AI architecture, and structured LLM output for hiring managers/recruiters reviewing the repo — success is measured by demonstrated engineering rigor (evidence-backed decisions, tested retrieval quality), not by user growth or production scale.
- (note) Non-goals (explicit out-of-scope): authentication, user accounts, payments, social/collaborative features, arbitrary PDF upload, arbitrary web scraping, general-purpose agent framework, autonomous browsing, multi-agent systems, fine-tuning/model training, sophisticated semantic chunking, complex reranking infrastructure, Elasticsearch, a separate vector database, Kubernetes, production cloud infrastructure, mobile app, and AI-driven UI generation (the app is a librarian pointing to documents, never an editor generating or altering the reading experience).
- (note) Success signal: a user asks a real question (e.g. 'What does Federalist No. 10 say about factions?'), receives an answer grounded in retrieved passages with server-verified citations, can click through to the cited paper and see the passage in context, and can independently verify the source via the Avalon Project link — end to end, locally runnable via npm run db:migrate / ingest:federalist-papers / dev.
